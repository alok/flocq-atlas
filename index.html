HOW TO READ THE ATLAS

A map for exploration.
Not a proof certificate.

Modules follow coqdep -sort. Within a module, declarations follow the positions recorded in Rocq’s compiled .glob files.

Solid lines show declaration dependencies; dashed lines show source order.

A name match can be ambiguous. The code panes let you inspect the actual hypotheses and bodies yourself.

Definitions (roots) is the default view. Definitions are roots and always show. A theorem is folded away only when it is proven (its Lean counterpart has no sorry and no proof-debt entry) and spot-checked by Claude against pinned Flocq, statement against statement. Every other theorem — unproved, unmatched, red, reviewed only by the port, or not yet checked — stays visible, and unproved theorems get a dashed red outline. A folded theorem’s dependency paths are compressed onto the nearest visible declarations it uses, which show a +n badge and list it in the inspector; each module also lists its folded theorems after its last page. All declarations shows the full graph.

A declaration is a theorem when Rocq compiles it as a proof of a proposition (dpdgraph’s prop flag), whatever its keyword. So Flocq’s Instances and Prop-valued Definitions count as theorems, and a Theorem that returns data, such as round_val_of_pred, counts as a definition.

Green marks checked slices. Amber means a counterpart exists but is not marked reviewed here. White means no match was found, not necessarily that the port is missing. Blue is the current review slice. Red includes open proof obligations, which do not necessarily mean an algorithm is wrong.

This is a read-only snapshot, built separately from the port. Source matching and excerpt boundaries are intentionally approximate. It does not update automatically.
